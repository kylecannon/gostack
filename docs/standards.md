# Standards

General Go style and testing follow
`agentic-harness/.agentic/conventions-go.md`. This file adds only the rules
specific to gostack.

## Code

- **Generated code** lives only in `internal/api/<svc>`. `make gen` runs the
  generator (`codegen/cmd/gostack-codegen`) over the services in `GEN_SERVICES`.
  - Header: `// Code generated by gostack-codegen. DO NOT EDIT.`
  - Never edited by hand. Change the generator or the vendored specs in
    `specs/`, then regenerate.
  - Excluded from lint and format. The exclusion filters reports only; the
    linters still read every file.
  - The generator splits each service's output across several files (types,
    codecs, operations) and never writes one giant file. A single 93k-line
    file costs the `whitespace` linter 16s per lint.
  - Sharded: a file whose declarations run past about 3,000 lines (`maxShardLines`
    in `codegen/cmd/gostack-codegen/emit.go`) becomes `<name>_1.go`,
    `<name>_2.go` and so on, cut at declaration boundaries. `make gen` deletes
    a generated file it no longer writes, so a shard that is no longer needed
    does not linger, and `make gen-check` fails on one that does.
  - A rest service's routing table is checked every time the generator runs: it
    refuses two operations that bind the same request. The per-operation test,
    `Test_routeRules_EveryOperation` in
    `codegen/cmd/gostack-codegen/route_internal_test.go`, sends each rule its
    own request and expects the operation back. It is built on the S3 model
    today, so a second rest service needs its own router builder there first.
- **Handler files.** One file per operation or tight operation group, for
  example `internal/service/sqs/send-message.go`.
- **Unimplemented operations** return 501 through the embedded generated
  `Unimplemented` struct. A handler never fabricates a result to make a test
  pass.
- **AWS errors** are generated typed error values. Handlers return them and the
  gateway serializes them. Handlers never panic. The gateway recovers a panic
  into 500 `InternalError`, or 501 under `FAIL_FAST`. The process keeps
  running.
- **State.**
  - Each service has its own `State`, held in `store.Bundle[State]` keyed by
    account and region. This mirrors `AccountRegionBundle` and
    `CrossRegionAttribute` in `localstack/services/stores.py`.
  - Locks are per shard and per resource. There is no global lock.
  - State types must serialize for persistence.
- **Cross-service calls** (SNS to SQS, Events to Lambda, CloudFormation to
  everything) go through an in-process client that dispatches through the same
  handler chain, so behavior is identical to an external call, as with
  LocalStack's `connect_to`. A service never reaches into another service's
  state.
- **No idle work.** No background goroutine runs while idle. Timers (SQS
  visibility, delays, TTL, persistence flush) are armed on demand from one
  per-service timer heap and stop when it is empty.
- **Hot paths do not use reflection**, and request and response bodies are
  streamed. Never buffer a whole S3 object. Spill to disk above 512 KB, as
  LocalStack's `SpooledTemporaryFile` does.

## Tests, cheapest first

1. **Unit tests** follow conventions-go.md: table tests, `testify/require`,
   `synctest` for time, `-race` always.
2. **Codec conformance.** `scripts/vendor-specs.sh` fetches botocore's
   protocol test fixtures (`tests/unit/protocols/{input,output}/{query,json,rest-xml,rest-json}.json`)
   into `internal/protocol/testdata/botocore` and records them in
   `specs/SOURCES.lock`. Every protocol a codec implements passes them: query,
   json, rest-xml and rest-json so far, and ec2 and cbor as their services
   arrive. Every Smithy trait the codec honors gets its own test.
   aws-emulator's dropped `@timestampFormat` is the cautionary case.
3. **Fuzzing.**
   - `go test -fuzz` on every parser: the protocols, SigV4, aws-chunked, the
     router, the DynamoDB expression grammar, and the JSONata parser.
   - Seed corpora are committed under `testdata/fuzz`.
   - `make fuzz` finds every `Fuzz*` function itself and runs each for
     `FUZZTIME` (default 30s); `make fuzz FUZZTIME=5s` is the quick form.
   - Nightly CI runs each fuzz target for 60s (see Gates).
4. **In-process service tests** use `aws-sdk-go-v2` against an `httptest.Server`
   running the real gateway. They cover only behavior the oracle does not, and
   regressions found in the field. rustack's three fixes are the first cases:
   - DynamoDB `LastEvaluatedKey` when `Limit` ends a page.
   - S3 `Expect: 100-continue` with an empty body.
   - SQS `MessageGroupId` on standard queues.
5. **Parity oracle** (see `architecture.md`). A service change is done when
   its ledger rows move to pass and none regress.
6. **Benchmarks** (below).

## Gates

Pre-commit and CI both run on the toolchain pinned in `go.mod`.

- **Pre-commit** runs `.agentic-quality`, the manifest the harness hook reads:
  `make fmt` on staged `*.go` files, then `make lint`, `make fix-check` and
  `make test` (`go test -race`) on the packages those files belong to. `make -s packages`
  finds those packages, and a failing `go list` fails the rule.
- **`make fix-check`** runs `go fix -diff` and fails on any diff; `make fix`
  applies it. Code uses the newest idiom the pinned toolchain offers, and
  `make fix-check` plus the `modernize` analyzers in golangci-lint enforce it:
  `go fix` follows the toolchain, `modernize` follows the linter's release.
- **CI** (`ci.yml`, on every pull request and every push to main) runs
  `make fmt FMT_ARGS=--diff`, `make tidy-check`, `make gen-check`,
  `make fix-check`, `make lint`, `make test` and `make build`.
- **`make gen-check`** (`ci.yml`) regenerates `internal/api` and fails on any
  modified file or untracked generated file.
- **Parity ledger** (`parity.yml`, on every pull request, and by hand with a
  `services` input) builds an image from the pull request head and runs
  LocalStack's own tests for the services the change touches against it, then
  `make parity-check`. It compares with the merge base of the pull request's
  base and head, and fails when there is none.
  - Selection is fail-safe: a changed path selects every service in the ledger
    unless it is one service's own path or cannot change the image.
  - A service's own paths are `internal/service/<svc>/` (which also selects
    the services that call `<svc>` in process), `parity/ledger/<svc>.json` and
    `parity/exclusions/<svc>.yaml`.
  - A change to `cmd/gostack/services.go` selects the services its changed
    lines name, or every service when a changed line names none.
  - `parity/ledger.py` lists the paths that cannot change the image
    (`NO_IMAGE_EFFECT`) and the in-process callers (`IN_PROCESS_CALLS`).
- **Parity ratchet** (`make parity-check`, in `parity.yml` and in `ci.yml`'s
  `parity-ledger` job): a test that is `pass` in the gostack column of the
  ledger at the base stays `pass`. Changing it to `fail`, `skip`, `xfail`,
  `excluded` or null fails the check, and so do removing its row and emptying
  its file. The check names every such nodeid.
  - The one exit is an entry in `parity/demotions.yaml`: the nodeid and a
    one-line reason, reviewed with the change.
  - An entry whose test is `pass` again fails the check until it is removed.
  - `make parity-prune` removes the rows whose test is gone from the pinned
    LocalStack and writes each removed gostack pass there as gone upstream.
  - The localstack column is not under the ratchet. Only its pass to fail
    fails the check, and any other change there is a warning.
  - `make parity-check` first runs the ledger's unit tests
    (`parity/test_*.py`). CI does not run the LocalStack baseline; the
    committed ledger is the baseline. The LocalStack suite comes from the
    commit in `specs/SOURCES.lock`, and the runner image is cached on that sha
    and `parity/runner/`.
- **benchstat** (`bench.yml`, every pull request) compares the micro benchmarks
  on the base and the head with `benchstat` and fails on a regression over 10%
  at p<0.05.
- **System bench regression** (`bench-system.yml`) runs `bench compare`: a pull
  request's head against its base on the quick profile, and a scheduled or
  manual run against the previous passing run on main with the same profile
  and host fingerprint, which is kept as a workflow artifact.
- **Fuzz** (`fuzz.yml`, nightly and by hand) runs `make fuzz FUZZTIME=60s`, which
  runs every `Fuzz*` function for 60s. A crash uploads the new
  `testdata/fuzz` entries and the log as the `fuzz-crashes` artifact.
- **Linters and formatters** are configured in `.golangci.yml` (v2 format).
  Linting runs in strict mode (`default: all`), and each disabled linter is
  documented there. `govet` runs with every analyzer enabled except
  `fieldalignment`, `exhaustive` treats a `default` case as exhaustive, and
  `gosec` is tuned there. Formatters are gofumpt and gci with two import
  groups.

## Toolchain

The Go version is pinned by the `toolchain` line in `go.mod`, or the `go` line
when there is none. The Makefile derives `GOTOOLCHAIN` from it, stops when both
are missing, and holds the reason for the layout below.

- **Make targets** run under that pin, golangci-lint included. golangci-lint is
  a tool dependency of its own module, `tools/go.mod`, run as
  `go tool -modfile=tools/go.mod golangci-lint`. The product `go.mod` carries
  none of its dependencies.
- **Editors and gopls** do not read the Makefile, so the pin does not reach
  them. Run `export GOTOOLCHAIN=$(make -s toolchain)` in the shell that starts
  the editor. Plain `go` commands outside `make` need it too.
- **Each module** has its own `go mod tidy`. Both `go mod tidy -diff` (root) and
  `go -C tools mod tidy -diff` must exit 0.

## Benchmarks

Every target is a number that gets measured. The first measurement sets the
baseline. After that, CI holds the line.

### Every feature ships its benchmark matrix

A feature is not done until its benchmarks cover the variants it can be called
with. A change that adds or alters a feature adds or updates its rows in the
same PR. A missing row is a review blocker.

| Axis | Values |
|---|---|
| Payload | small (under 1 KiB), medium (about 64 KiB), and the service's maximum |
| Concurrency (system bench) | 1, 16, 64 |
| Wire protocol | every protocol the service speaks (SQS: query and json) |
| Feature options | each option that changes the code path, e.g. SQS standard vs FIFO, single vs batch, short vs long poll, with and without message attributes |
| Persistence | off, and on (`PERSIST_SQS=1`) for services that persist |

Name sub-benchmarks so benchstat lines them up across runs:
`BenchmarkSendMessage/proto=json/queue=fifo/payload=64KiB`. An axis that does
not apply to a feature is left out, not filled with a placeholder.

A micro benchmark's persistence-on rows sit under the same function as its
persistence-off rows, with a `persist=on` key first
(`BenchmarkPutObject/persist=on/payload=1MiB/concurrency=16`) and no key for
off, so the base's rows keep their names. `benchstat -col /persist` sets the two
side by side.

### Micro benchmarks

- Live in `*_benchmark_test.go`, loop with `b.Loop()`, and report bytes with
  `b.SetBytes` where a payload is involved.
- Cover:
  - routing;
  - each protocol codec, decode and encode, across the payload axis;
  - SigV4 parsing;
  - every service operation's handler path, across its matrix.
- benchstat (see Gates) compares `-count=10` runs on main and on the PR. A
  regression over 10% with p<0.05 fails the build unless it is accepted
  (below).

### System bench (`bench/`)

The same workload runs against `gostack:latest`, `gostack:slim` and the
LocalStack image. Measured:

- time from container start to `Ready.`;
- idle RSS, and idle CPU over 60s (target: no wakeups), with the image
  HEALTHCHECK on and off;
- RSS and CPU under load;
- p50 and p99 per operation for each cell of the feature matrix;
- image size.

An "agentic" workload runs many short create, use and delete cycles across
every implemented service. Results are committed to
`bench/results/<date>-<sha>.json` as human records. `go run ./bench compare`
checks a run against the newest committed result with the same host
fingerprint and fails when a gostack cell regresses past its threshold;
`make bench-system` runs it after measuring. CI never compares against the
committed files, because a runner never has the fingerprint of the machine
they came from: the scheduled run compares with the artifact the previous
passing run on main uploaded. LocalStack cells are reference numbers and never
gate. A latency also has to rise by 0.05 ms (p50) or 0.5 ms (p99) to regress,
so a tick of the 0.01 ms resolution at c=1 cannot fail the gate.

### Accepted regressions

A regression accepted as the cost of a change is listed in
`bench/accepted.yaml`, in the pull request that brings it, with its metric,
the largest change accepted, a one-line reason, the pull request and a commit
that carries the cost. Both CI gates read the file and print what it holds
under "Accepted". A listed metric past its bound, and every unlisted one, still
fails. A bound is a finite number above zero with at most one leading `+`, as
`+50%` or, for a system metric, `6 MiB` (units `MiB`, `ms`, `s`, `cycles/s`);
an infinite, negative, zero or repeated-sign bound is a load error, as is a
second entry for one metric or a second YAML document. An entry's `package` is
the full import path or the path below the module (`internal/route`).

An entry applies only while the head holds its commit and the base does not, so
it expires once main holds the commit. The pull request lands with a merge
commit, never a squash: a squash or rebase merge leaves the commit out of main,
so the entry never expires. Delete the entries in the first change after the
merge.

A result file is schema 3. A cell id is `<service>/<workload>/<options...>`,
such as `sqs/messaging/persist=off/payload=256B/queue=standard/shape=single/proto=json/c=16`.
A cell holds its operations as a map from name to latency, and declares the
environment variable that turns its persistence on. A service is added by
registering a workload in `bench/` (`Service`, `Name`, `Ops`, `Cells`, `Run`);
the report and the compare gate read the operations from the result and name
none. A file of schema 2 is converted when it is loaded.

### Runtime knobs

- Services start lazily on first request. `EAGER_SERVICE_LOADING` is honored.
- `GOMEMLIMIT` is honored, and Go is container-aware about `GOMAXPROCS`.
- Buffers come from `sync.Pool`.
- pprof is served only when `DEBUG=1` (path in `architecture.md`).
